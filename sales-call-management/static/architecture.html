Sales Call Management — system architecture

A recorded sales call arrives as a transcript. The Discovery Agent reads it and updates a JSON CRM; the Reporting Agent answers questions live from that same CRM. Both agents run a local Messages-API tool loop against claude-opus-5-5 — no cloud agent runtime.

Ingest / write path Reporting / read path Dashboard & shared infra Response / stream back JSON file stands in for a CRM .md files stand in for a vector DB

1 · Ingest a call

A transcript (or the Ingest button → POST /api/calls/ingest) hands the markdown to the Discovery Agent. It reads the current CRM, reconciles entities, and writes accounts, contacts, opportunities and a logged activity back to crm.json.

2 · Ask for the freshest data

The chat panel streams a question to POST /api/chat. The Reporting Agent runs read-only tools against the live CRM and streams a grounded answer back over SSE — always reflecting the latest ingest.

3 · Dashboard

GET /api/dashboard aggregates crm.json directly in Python — no model call — for stat tiles, pipeline-by-stage, open deals and recent activity. Re-fetched after an ingest so the board visibly updates.
